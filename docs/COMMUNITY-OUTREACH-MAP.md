**Not:** “hire blockchain developers”

## Why these people (not “crypto clones”)

| Their hard problem | StrataMesh surface |
|--------------------|--------------------|
| Peer discovery, NAT, gossip, intermittent peers | GDA mesh / multi-host testnet |
| Edge orchestration, device as resource | Fog Node → Edge population |
| Content addressing, availability | IPFS client, object CIDs, proofs |
| Strangers contributing compute for pay | PdC / PdS / Agora (lab economics) |
| Long-running stateful agents | SCA volition, standing, wallets |
| Persistent multiplayer worlds | Holonic stack: Domain → World → Sandbox |

The ideal contributor often sits at an **intersection** (few people have all six): distributed systems + edge + P2P + agents + economic mechanisms + virtual worlds. The **testnet** and **Impact Fund** are convergence points.

---

## How we invite (message discipline)

**Do say:**  
“We’re building an open computational substrate. If you work on P2P, edge, distributed systems, autonomous agents, decentralized compute, IoT, OS, or simulation, there is a layer that is **your** problem.”

**Don’t say:**  
“We’re looking for blockchain developers” / “competitor to X.”

**Do:** problem-first issues, measurable acceptance criteria, Fund challenges.  
**Don’t:** absorb roadmaps or rebrand other projects.

## Operational checklist (lab)

1. Open **problem** issues with objective metrics (not vague “improve networking”).  
2. Tag `track:*` + `good first issue` or `impact-challenge` when funded.  
3. Link Fund challenge ↔ GitHub issue.  
4. Review PRs against lab honesty (not mainnet claims).  
5. Update this map when a community’s relevance shifts after evidence.
